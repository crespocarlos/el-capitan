# Carlos's writing style

Derived from work-related Slack messages and intended only for Impact Connection / IDP writing.

## Voice

- Direct, practical, and candid.
- Explain the system or problem before listing implementation detail.
- Use plain language over performance-review jargon.
- State uncertainty, tradeoffs, and remaining work plainly.
- Make claims proportional to the evidence; avoid inflated ownership or generic impact statements.

## Structure

- Prefer short paragraphs and compact bullets.
- Lead with the key point, then explain the mechanism or reason.
- Name concrete concepts and decisions instead of abstract labels.
- Connect technical work to the operator, system behavior, or team decision it affects.

## Adaptation for IDP writing

- Keep Slack's clarity and straightforwardness, but remove conversational fillers, shorthand, typos, and informal asides.
- Use complete sentences and professional first-person language.
- Do not sound promotional; let scope, outcome, and learning establish impact.
- Prefer “I simplified X because Y” over “I drove transformational excellence.”

## Avoid

- Empty verbs: “leveraged,” “synergized,” “spearheaded” unless they add precision.
- Generic claims: “significant impact,” “cross-functional collaboration,” or “strategic initiative” without a concrete example.
- Long inventories of PRs, implementation details, or tools without explaining why they mattered.
