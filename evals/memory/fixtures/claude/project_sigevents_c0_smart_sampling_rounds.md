Goal (user): keep LIMIT 5 and control context using Agent Builder alone (no sandbox, no new sampling tool); explore smart KEEP/DROP; investigate low-cardinality fields; 3 best options with evidence. Experiments are read-only on c0 via the console proxy (see [[c0-access-howto]]); context in [[sigevents-c0-context-compaction]].

## Round 1: constants-over-window + twin columns via a per-source probe (DROP)
Method: probe every mapped column (COUNT, COUNT_DISTINCT over the last hour, latest 3000 rows), DROP columns constant over the window plus .keyword/.text twins, re-run real rule predicates (LIMIT 5), compare response size and verify dropped constants against the probe value.
Results: autoops-backend 715 mapped columns, 38 constant, 24 twins -> only 8% smaller (host.ip/mac arrays dominate); ams-logs 240 mapped, 87 constant, 5 twins -> 43% smaller, 0 mismatches.
Learnings: (1) savings vary by what dominates the source (arrays vs infra constants); (2) a LIMIT-capped probe is not a sound window: 5 of 1,140 constant cells mismatched on autoops because 3000 latest rows cover less than the sample window, so constants must be taken over the same window; (3) the probe is expensive (hundreds of COUNT_DISTINCT over 700 mapped columns took minutes for two sources), not viable as an agent step; (4) mapped columns (715) far exceed returned non-null columns (~150), and DROP of a mapped column is valid for every predicate of that source even when null, so a per-source plan is stable.

## Round 2: cardinality classes and relevance (offline, 1,029 c0 samples)
Share of sample chars by class: bulky multi-valued (>=20 values; host.ip/mac) autoops 65%, eis 60%, agentless 42.5%, control-plane 19%, ams 11%, cphosted 0; same-field twins ams 28%, cphosted 25%, agentless 11%; exact duplicates under different names 7-15% everywhere; constant across the 5 rows 9-23%; long text (>500 chars, stack traces) ams 29%, control-plane 23%, agentless 12%; varying + low-cardinality columns only ~10-25% of bytes on the big sources.
Columns: 80-113 of 140-200 columns per sample are constant across the 5 rows (infra context: cloud/agent/kubernetes labels), only 18-43 vary. Low-cardinality columns are the dimensions (level, service, region) and are cheap; the bytes are in constants, arrays and twins.
Learnings: (1) the diagnostic part of a row is small; the lossless win is hoisting constants once and merging twins/duplicates, which needs code (a tool), not a query; (2) query-level hoisting is infeasible without writing hundreds of column names (a STATS over 715 columns is ~4k tokens of query text); (3) a per-source DROP plan is stable (mapped columns valid for every predicate), so DROP lists work if the list is short (twins: 5-24 names); (4) KI dataset_analysis (per-source value frequencies, capped at 150 fields, missing for 3 of 7 sources, sampled from 1000 docs) is not a reliable constants source; (5) arrays are name-specific (host.*) so dropping them is a policy call, not a mechanical rule.

## Round 3: compare candidate designs on 1,029 c0 samples (offline) and settle the top 3
- Allow-list KEEP of ~60 ECS dimension patterns (investigator style): keeps 9-67% of bytes (autoops 11%, eis 9%) but fails CLOSED: drops unknown/custom fields and 49-93% of varying bytes (mostly host arrays and identity aliases). Rejected (information loss, hypothesis-shaped).
- Fail-open deny-list DROP (host.ip/mac, agent.id/ephemeral_id/version, elastic_agent.*, ecs.version, data_stream.*, cloud.instance.id/machine/account/provider, kubernetes.pod.uid/ip, node labels/uid/hostname, log.offset/inode, orchestrator.*, @version, event.ingested + verified twins): removes 60% of bytes overall (autoops 81%, eis 79%, agentless 65.5%, ams 53%, control-plane 52%, cphosted 26%), unknown fields stay. Varying columns it removes are identity aliases/offsets (log.offset, kubernetes.pod.uid/ip, host.ip/mac, agent.ephemeral_id, cloud.instance.id); host.name, pod name, node name, container id remain. Cost: DROP of an unmapped name/pattern errors, so one tiny `KEEP <prefix>* | LIMIT 0` probe per deny prefix and per source (+1 cycle), and `*.text` can be a real field (OTel `body.text`), so twins need the base column checked.
- Lossless rendering in a tool (verified twin merge + exact-duplicate aliasing + hoisting constants + text lines): -37% overall (27-54% by source), no policy call; needs a tool (future sampling tool/sandbox).
- Bounded exposure (sequential per-sample cycles + batch size 3-5 drained by the review loop): no fidelity loss, removes the restarts at c0 widths, stacks with either trim.
Top 3: (1) bounded exposure now; (2) lossless tool rendering when a tool/sandbox exists; (3) fail-open deny-list DROP in two tiers (safe: twins + offsets + ingest/build metadata; policy: host arrays and pod/instance ids) only if bounded exposure is not enough. Upstream asks: per-cell cap for multi-valued arrays, intra-run summarizers, read_file range.
