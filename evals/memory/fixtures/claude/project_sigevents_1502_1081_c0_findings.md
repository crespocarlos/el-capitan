Measured on c0 (access: `~/Documents/dev/nightshift-c0-debug`, `./c0-kibana.sh`, ES via console proxy; read-only), 2026-10-14.

- Discovery cost ~$390 over 8 days (525 runs, ~66 runs/day, ~$49/day). 56% of runs only produced `unchanged_outcome`/`existing_active_event` (58% of cost); 11% judged rules not event-eligible (7%); only 31% wrote anything. ~400k input tokens per run for a median of 2 rules, so cost is per run, not per rule.
- Back-test of #1502's rule "skip a rule already a member of an active series": 77% of the unchanged-only runs were fully skippable (~45% cost cut, upper bound). Of 90 real-write runs, 9 would be fully skipped: 8 were discovery closing an event (`active->inactive`, recovery reconciliation), 2 were a member joining. So a blanket skip delays the closure path; a pre-check (stored signal query still returns rows) guards it, and `change_point_type` cannot (4 of 6 closures were spikes).
- Born-inactive cooldown in #1502 targets <=7% of cost (born-inactive series are now rare, 3/55). Prior-verdict context is a quality lever, not a cost lever: split it out.
- #1081 continuity: legacy corpus (`.significant_events-events`, 18.5k events, to 2026-10-07) replays to 81% eligible, but 92% had a never-real predecessor (discovery's own dismissals, no longer written). Real recurrences ~1.2k in 3 months (~13/day). Current era: exact identity continues 5% (3/55); 28 of 46 rule re-appearances are concurrent with a live series (membership growth, not continuity). No operator `deactivate` has ever been recorded on c0.
- Prior verdicts already exist in `data.signals[]`: 84% of processings since Oct 8 (97% incl. legacy) were for rules with a stored signal. A processed marker only has `detection_id` + `processed_by`.
- The agent's `written` flag is unreliable (93 items `written:true` with `unchanged_outcome`); count from `.rule-events`.

**Why:** the user challenged whether each ticket solves its stated problem; cost is the pain, and noisy detections re-trigger discovery with unchanged outcomes.

**How to apply:** order is #1502 cost half (pre-agent skip of active-series members, empty batch exits before the agent), then #1502 context, then #1081 (a correctness/notification fix, not cost). Success metrics: runs/day, cost/day, unchanged-only share, real-write runs not lost, closure delay (no new age throttle; skip needs live membership plus a deterministic pre-check, shadow mode first). **Decision 2026-10-15 (#1502 skip granularity):** classify per detection, not all-or-nothing. A detection that needs the agent must reach it; skippable ones are dropped from the batch and stamped processed (merge with the agent's `written_rule_uuids`). Probe every live-member detection via one custom step (`significantEvents.classifyDetections`, parallel probes, per-probe timeout, fail-safe to `needs_agent`). Decision table: member state x rows from re-running the stored signal query over >= detection lookback (60m): breaching+rows skip; breaching+no rows agent; healthy+rows agent; healthy+no rows skip; unjudged/error/timeout/no_query agent. Shadow mode gate: about a week or >= 20 discovery closures (they are ~2.3/day) for closure recall, plus a probe error-rate gate. Baselines = trailing 7 days frozen at shadow start (this week Mon Oct 12 - Thu 11:30Z: 83 runs/day, ~$65/day, 63% unchanged-only).

**Analysis 2026-10-15 (POC vs target arch, tested on c0):** Tony's POC (`tonyghiani:poc/detection-engine-prototype`, RFC nightshift-program#1348) is the doc's prepared-case design (code builds bounded case, agent only calls `submit_assessment`, citations validated), its §7 option (b) baseline-alone (median+MAD, floor, no change_point), the same lifecycle table, a per-detection outcome record (11 outcomes), a dismissal hold (value x1.25, no expiry) and a cooldown (no agent when only facts changed). On 155 single-rule c0 runs with stored queries (6 recovery closures): the classifier probe window decides closure recall. Rows in last <=30m routes 6/6 closures to the agent (and skips 99% of unchanged); 45m -> 5/6; 60m -> 3/6. So default `classifierProbeWindowMinutes` 60 is wrong; data says ~20. POC baseline (own history) marks 91% of unchanged as background and 100% of closures as background, so it is a novelty/elevation test, not a recovery or state-agreement test; the two gates are complementary. Excluding live-episode windows (doc §1, POC) leaves <10 samples in 112/155 cases (rules sit in long-open events), so the exclusion starves the baseline on c0 until events actually close. Not run: the POC itself.

**Implemented 2026-10-15 (after the POC analysis):** probe window default 20 min (was 60); probe appends commands on a new line (a stored query ending in a `//` comment swallowed ` | LIMIT 1`); shadow-only baseline per probed detection (`baseline.ts`: median + MAD band, floor 3, 5-min buckets x 60, injected `observe` so other detection kinds can plug in; recorded on the decision, never acted on; only runs in shadow mode). Decision path (LIMIT 1 probe) unchanged. No exclusion-window variant (it starves the baseline on c0) and no new workflow inputs, to keep the change small. Semantic Code Search and Elastic Docs MCPs needed OAuth, so research used a subagent and web docs. Adjudication of the baseline is the user's call.

**Decision 2026-10-15 (baseline adjudication, user chose the defaults, conditional on "provided it will improve things"):** adjudicate only after >=14 days of shadow data and >=20 discovery closures. Labels `real | chronic | unsure` (unsure excluded), by two independent people plus a tie-break, never the agent and never investigation outcomes alone; ~120 labels, blind to baseline decision and agent outcome, oversampling non-live detections where the agent wrote but baseline said background, the above_normal cases and the recoveries. Parameters frozen as shipped (5-min buckets x 60, MAD band 3, floor 3), one pre-declared iteration. Pass = agreement >=70% AND false suppression of `real` <=10% AND closure recall stays 100% AND a measured reduction in agent runs/cost with no regression in real writes; 50-69% = one iteration; fail = stay shadow-only and fall back to investigations' triage. On pass, enforce only for non-live detections. Expected upside on c0 (estimate): certain <=~7% of cost (the "not event-eligible" runs), up to ~25% more only if the suppressed non-live writes prove to be noise; the baseline's main value is quality (noise and escalation), not cost.

**Research 2026-10-16 (what the classifier could offload from the agent):** 79 c0 runs (Oct 15-16) + 254 local runs. Median run: 1 rule, 8 LLM calls, ~380k input tokens (c0, ~71% cached), ~29k tokens of tool results, so cost = context x turns, not result size. Per run (c0): load_skill 1, ki_search 2, confirm queries 1.3, profile queries 2.9 (local 8.5), event_search 3.1, events_write 1. ~4 reasoning turns before routing, ~2 after. Confirm queries return rows 80-91% (only 9-20% empty = mechanically decidable); 16% of c0 profile queries error. Candidate offloads: prefetch ki_search, run confirm+profile in a step, hand live-member event_id + stored signal verdict (73% of detections) so event_search shrinks. Stays with the agent: on-topic judgement of rows, topology, incident matching, narrative, severity. Tension: prompt requires every cited number to come from a result read in this run. Savings estimate (~up to half of agent-run input tokens) is unmeasured; needs an eval.
